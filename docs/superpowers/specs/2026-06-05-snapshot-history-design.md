# 月度快照与历史统计设计方案

## 1. 概述

在当前财务分配器中新增三项能力：

- 保存快照：将当前页面配置和当月计算结果保存为当前自然月快照。
- 恢复快照：读取当前自然月快照，覆盖当前页面数据并刷新。
- 历史统计：跳转到独立历史页面，按年份、月份、执行人和投资子项查看历史投资明细与汇总。

第一版使用本地 SQLite 数据库保存月度快照和历史统计数据。现有 `data.json` 继续作为当前页面配置的读写来源，避免打断当前实时保存逻辑。

## 2. 数据模型

数据库文件放在项目根目录，建议命名为 `finance.db`。服务启动时如果数据库或表不存在，则自动创建。

### 2.1 月度快照主表

`monthly_snapshots`

| 字段 | 说明 |
| --- | --- |
| `month_key` | 月份主键，格式 `YYYY-MM` |
| `config_json` | 保存当时完整 `data` 配置，用于恢复快照 |
| `summary_json` | 保存当时计算摘要，如总收入、固定支出、可支配资金、交易日信息 |
| `created_at` | 首次创建时间 |
| `updated_at` | 最近更新时间 |

同一个 `month_key` 只保留一份快照。重复保存时覆盖当前月旧数据。

### 2.2 投资明细表

`snapshot_investment_items`

| 字段 | 说明 |
| --- | --- |
| `id` | 自增主键 |
| `month_key` | 所属月份 |
| `assignee_id` / `assignee_name` | 执行人 |
| `category_name` | 一级分类名称 |
| `subcategory_name` | 二级子项名称，没有二级子项时可为空 |
| `item_name` | 历史页展示用投资项名称 |
| `monthly_amount` | 月投入金额 |
| `daily_amount` | 日投入金额；存款项为空 |
| `trading_days` | 当月交易日数 |
| `is_estimated_trading_days` | 交易日是否为估算 |

统计口径：所有 `投资/理财` 明细都进入历史统计，包括名称包含“存款”的项目。存款项纳入总投资额，但日投入显示为空。

### 2.3 成员结算表

`snapshot_member_balances`

| 字段 | 说明 |
| --- | --- |
| `id` | 自增主键 |
| `month_key` | 所属月份 |
| `member_id` / `member_name` | 成员 |
| `income` | 成员本月收入 |
| `target` | 成员本月总任务 |
| `balance` | 成员结余或缺口 |

该表用于后续扩展历史结算统计；第一版历史页面可以先不重点展示，但保存快照时同步写入。

## 3. 服务端接口

新增 SQLite 访问层，封装建表、保存快照、读取当前月快照、查询历史统计。接口保持轻量，不引入前端构建流程。

### 3.1 保存当前月快照

`POST /api/snapshots/current`

请求体由前端提交：

- `monthKey`
- `config`
- `summary`
- `investmentItems`
- `memberBalances`

服务端行为：

- 校验 `monthKey` 为 `YYYY-MM`。
- 在事务中 upsert `monthly_snapshots`。
- 删除当前月旧的 `snapshot_investment_items` 和 `snapshot_member_balances`。
- 写入当前月新的投资明细和成员结算记录。
- 返回 `{ ok: true, monthKey }`。

### 3.2 读取当前月快照

`GET /api/snapshots/current`

服务端按当前自然月读取 `monthly_snapshots`。

- 有快照：返回 `{ ok: true, snapshot }`，其中 `snapshot.config` 为完整配置。
- 无快照：返回 `404` 和 `{ ok: false, error: "snapshot_not_found" }`。

### 3.3 历史统计查询

`GET /api/history?year=2026&month=06&assignee=刘&itemKeyword=纳指`

筛选参数均可选。返回：

- `items`：筛选后的投资明细。
- `summary`：总投资额、平均日投入、涉及月份数。
- `groupedByAssignee`：按执行人汇总。
- `groupedByItem`：按投资子项汇总。
- `groupedByMonth`：按月份汇总。
- `filters`：可用于页面筛选项的数据，如可选年份、月份、执行人列表。

## 4. 主页面交互

在当前页面顶部 Header 或“月度资金核算单”附近新增三个按钮：

- 保存快照
- 恢复快照
- 历史统计

交互规则：

- 保存快照：保存当前自然月快照。如果本月已保存过，则覆盖旧快照，并提示“已更新 YYYY-MM 快照”。
- 恢复快照：先弹确认框，提示会覆盖当前页面数据。确认后读取当前月快照，将 `snapshot.config` 替换为当前 `data`，调用现有渲染逻辑刷新页面，并同步写回 `/api/config`。
- 恢复失败：如果本月没有快照，提示“本月暂无快照”，不改变当前页面。
- 历史统计：跳转到 `/history.html`。

保存快照时，前端基于当前页面已有计算逻辑生成：

- 完整 `data` 配置。
- 月度摘要：总收入、固定支出、可支配资金、交易日数、交易日来源。
- 投资明细：从核算单投资/理财明细生成，包含执行人、分类、子项、月投入、日投入。
- 成员结算：来自当前 `calculateSettlement()` 的成员余额结果。

## 5. 历史统计页

新增 `history.html`，沿用当前页面视觉风格，不做配置编辑，只做查询和汇总。

页面结构：

- 顶部导航：标题、返回当前配置页。
- 筛选区：年份、月份、执行人、投资子项关键词。
- 汇总卡片：总投资额、平均日投入、涉及月份数。
- 分组汇总：按执行人、按投资子项、按月份。
- 明细表：月份、执行人、投资项、月投入、日投入、交易日数、交易日是否估算。

统计口径：

- 总投资额：筛选后所有投资明细的 `monthly_amount` 之和，包含存款。
- 平均日投入：只统计有 `daily_amount` 的非存款投资项。
- 存款项：显示在明细和投资项汇总中，日投入显示 `—`。
- 估算交易日：日投入前显示“约”，并在明细中标识。

## 6. 边界情况

- 当前月没有快照：恢复时只提示，不改数据。
- 同月重复保存：覆盖旧快照，不创建多版本。
- 分类比例超过 100%：仍允许保存，历史页按当时生成的计算结果展示。
- 服务端或数据库异常：按钮提示失败，不影响当前页面继续编辑。
- SQLite 文件不存在：服务启动时自动创建。
- 旧 `data.json`：继续兼容，不要求迁移历史。
- 直接打开 `index.html` 文件：快照和历史统计依赖服务端 SQLite，需通过本地服务访问。

## 7. 验收与测试

- 保存当前月快照后，数据库中该月只有一条主快照，并有对应投资明细和成员结算记录。
- 修改页面数据后恢复快照，页面回到当月保存时的配置状态。
- 连续保存同一个月两次，第二次覆盖第一次。
- 历史页按年份、月份、执行人、投资子项关键词筛选结果正确。
- 历史页总投资额等于筛选后明细 `monthly_amount` 总和。
- 历史页按执行人、投资子项、月份汇总金额正确。
- 存款项出现在历史统计中，但日投入显示为空。
- 非存款投资项日投入等于 `monthly_amount / trading_days` 四舍五入。
- 估算交易日的日投入显示“约”。
- 现有主页面收入、固定支出、分配、结算、转账建议和日投入功能不回退。
